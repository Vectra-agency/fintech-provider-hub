## 0. Как работать с этим документом

У проекта **два референса** с чётко разделённой зоной ответственности.

### Референс контента: `docs/prototype/index.html`

Это рабочий прототип: одностраничное приложение в одном файле. Из него берётся:

- тексты сайта — объект `T` (EN и RU);
- тексты экранов телефона — объект `SS`;
- тексты мокапа админки — объект `ADM`;
- состав страниц.

Порядок секций и их оформление теперь задаёт раздел 6 этого документа, а не `PAGES` прототипа.

### Референс дизайна: https://qronos-ai-agent-scheduler-template-v1.21st.app/

Из него берутся:

- визуальный язык: цвета, типографика, сетка, скругления, тени, фоны;
- паттерны секций;
- анимации и микровзаимодействия;
- **видео hero целиком**.

Снимок референса (скриншоты, токены, видеофайлы) сохраняется в `docs/design-reference/` на этапе M1 (раздел 4.3.1).

### Что НЕ берём из референса дизайна

- тексты;
- название и логотип Qronos;
- логотипы компаний в бегущей строке;
- отзывы, аватары, тарифы;
- картинки (кроме видео hero);
- строку «All systems operational»;
- любые цифры и метрики.

### Правило конфликта

**Контент и комплаенс важнее дизайна.** Если паттерн референса требует того, чего нет в нашем контенте (цифр, цитат, логотипов), элемент убирается. Придумывать содержимое под паттерн нельзя.

### Прочие правила

- Тексты не переписываются, не сокращаются и не дополняются, особенно юридически чувствительные формулировки (раздел 9).
- Изменения поведения относительно прототипа помечены **[новое]**.
- Нерешённое помечается в коде как `TODO(Qn)` со ссылкой на вопрос из раздела 15.

## 1. Контекст и цели

Fintech Provider Hub — финтех-компания из Гонконга, разработчик и интегратор white-label финансовых продуктов. Сайт маркетинговый, B2B. Направления:

| Направление | Статус |
|---|---|
| White Label Crypto Wallet (Telegram Mini App) | Core product |
| Crypto Card Programs | Via partners |
| Global Payment Solutions | Via partners |
| Custom Fintech Development | Service |

**Главная конверсия** — переход в Telegram `@fintechprovider` с заготовленным сообщением. Форм, аккаунтов и бэкенда нет.

### Цели

1. Запустить двуязычный сайт (EN/RU) с контентом прототипа в дизайне референса.
2. Каждая страница каждого языка — отдельная индексируемая страница. Прототип использует hash-роутинг и рендерит всё через JS, поэтому поисковики его фактически не видят.
3. Измерять воронку: просмотр → клик по CTA → копирование сообщения → переход в Telegram.

### Метрики успеха

| Метрика | Цель |
|---|---|
| Индексация | Все индексируемые страницы обоих языков в Google и Яндексе через 4 недели после запуска |
| Lighthouse (mobile) | ≥ 90 по Performance, ≥ 95 по Accessibility, Best Practices и SEO |
| Core Web Vitals (p75) | LCP ≤ 2,5 с, CLS ≤ 0,05, INP ≤ 200 мс |
| Конверсия в Telegram | Фиксируем baseline за первый месяц |

Порог Performance снижен до 90 из-за видео в hero.

## 4. Стек и архитектура

### 4.1 Стек

| Слой | Решение | Почему |
|---|---|---|
| Фреймворк | Next.js (App Router) + TypeScript `strict`, `output: 'export'`, `trailingSlash: true` | Полностью статичный сайт |
| Стили | Tailwind CSS v4 + CSS-переменные с токенами из референса | Шаблоны 21st собираются на Tailwind; так проще переносить паттерны |
| Анимации | CSS + IntersectionObserver; Motion — только в клиентских островах и в рамках бюджета JS | Повторить анимации референса без лишнего веса |
| Шрифты | Шрифты референса через `next/font` (self-hosted), подмножества `latin` и `cyrillic` | Без кириллицы RU-версия ломается (см. Q11) |
| Контент | Типизированные TS-словари | Паритет EN/RU проверяет компилятор |
| Медиа | Видео и постер лежат у нас в `public/media/hero/` | Не зависим от чужого хостинга |
| Хостинг | Cloudflare Pages + одна Pages Function на `/` | |
| CI | GitHub Actions | |
| Тесты | Playwright + `@axe-core/playwright`, Lighthouse CI | |
| Аналитика | Провайдер без cookies через адаптер (Q2) | Требование Privacy Policy |

### 4.2 Принцип рендеринга

Все страницы статически рендерятся на билде, весь текст есть в HTML без JS.

Клиентский JS используется только в островах:

- `Header`;
- `HeroVideo`;
- `Marquee` (только пауза; сама анимация на CSS);
- `ShowcaseTabs`;
- `BrandSwitcher`;
- `LeadBlock`;
- `ScaleToFit`;
- `Reveal` — анимации появления при скролле.

### 4.3 Дизайн-система

#### 4.3.1 Снятие дизайна с референса (этап M1)

Скрипт `scripts/extract-reference.ts` на Playwright открывает референс на ширинах 1440, 768 и 390 px и сохраняет в `docs/design-reference/`:

1. **Скриншоты:** полноэкранные скриншоты страницы и отдельные скриншоты каждой секции.
2. **Стили:** `tokens.json` с вычисленными стилями ключевых элементов — `body`, `h1`, `h2`, `h3`, `p`, ссылки навигации, основная и вторичная кнопки, карточки, фреймы с интерфейсом, фоны секций, рамки, тени, скругления.
3. **Шрифты:** список `@font-face` и шрифтов, которые реально используются.
4. **Переменные:** все CSS-переменные, объявленные на `:root`.
5. **Анимации:** параметры анимаций и переходов — `transition`, `animation`, длительности, кривые, задержки появления при скролле.
6. **Видео hero:** все `<source>` у `<video>` в hero, атрибуты `poster`, `autoplay`, `loop`, `muted`, `object-fit`, `object-position`, а также оверлеи и градиенты поверх видео. Файлы скачиваются в `docs/design-reference/media/`.

По результатам:

- токены переносятся в `src/styles/tokens.css` и тему Tailwind;
- видео готовится по разделу 7.1.

Источник правды по визуалу — скриншоты, а не моё описание ниже.

#### 4.3.2 Что известно о референсе по структуре

Это наблюдения по структуре страницы. Каждый пункт сверяется по снимку из 4.3.1.

#### 4.3.3 Наши элементы в новом стиле

| Элемент | Правило |
|---|---|
| Логотип | Наш, `LOGO` из прототипа. Логотип Qronos не используем |
| Подписи кнопок | Регистр задаётся стилем (например, `text-transform: uppercase`, если так в референсе); тексты в словаре не меняются |
| Экраны телефона | Внутренний дизайн экранов сохраняется: это продукт клиента, и он перекрашивается палитрой бренда. В стиле референса делаются только корпус телефона и фрейм вокруг |
| Мокап админки | Перерисовывается в стиле app shell референса. Тексты, демо-данные и структура (сайдбар, KPI, таблица, тикет) не меняются |
| Пилюли статуса | Оформляются в стиле референса. Четыре статуса различаются и цветом, и текстом, а не только цветом |
| Палитры бренда | ember `#F04800` (по умолчанию), ocean `#2F6BFF`, mint `#0E9F6E`, iris `#7C3AED` — действуют только внутри мокапов |
| Цифры | Только из контента прототипа. В слотах метрик стоят пилюли статуса или факты из `specs` |

| Terms of Use | `/en/terms/` | `/ru/terms/` | `#en-terms` |
| 404 | `/404.html` | — | — |

### Правила

- **Корень `/` [новое].** Pages Function делает 302-редирект по `Accept-Language`: `ru*` → `/ru/`, всё остальное → `/en/`. В ответе передаётся `Vary: Accept-Language`. Запасной вариант без функции — `_redirects`: `/ /en/ 302`.
- **Якоря главной:** `/{lang}/#solutions` и `/{lang}/#features`, с `scroll-margin-top` под sticky-шапку.
- **Переключатель языка** ведёт на ту же страницу (и тот же якорь) в другом языке.
- **404:** `noindex`, язык определяется по префиксу пути на клиенте, по умолчанию EN.
- **Ссылки на Telegram:** `target="_blank" rel="noopener"`.

### Шапка (в стиле референса)

- **Левая часть:** логотип.
- **Навигация:** Solutions (выпадающее меню из 4 решений с кратким описанием), Platform Features, Projects, About Us, Contact.
- **Правая часть:** переключатель EN/RU и «Request a Demo».
- **На узких экранах:** бургер и полноэкранное меню.

### Подвал (в стиле референса)

- **Колонки:**
  - логотип со слоганом (`footer.tag`) и ссылкой на Telegram;
  - Solutions;
  - Company;
  - Legal.
- **Нижняя строка:**
  - дисклеймер (`footer.disc`) — вместо «All systems operational»;
  - © (`footer.rights`).

## 7. Интерактивные компоненты

### 7.1 HeroVideo [новое]

#### Источник

- **Что переносим:** видео hero с референса целиком — все варианты `<source>` и постер. Визуально 1:1: тот же кадр, кадрирование, длительность, луп, оверлеи и градиенты поверх.
- **Что можно менять:** только кодек и битрейт.
- **Где храним:** файлы лежат у нас в `public/media/hero/`. Ссылаться на файлы референса напрямую (хотлинк) нельзя.
- **Права:** нужно подтвердить право использовать шаблон и видео на коммерческом сайте (Q9). До подтверждения видео используется только на превью-деплоях.

#### Подготовка файлов

| Вариант | Формат | Цель по весу |
|---|---|---|
| Десктоп (≤ 1920 px по ширине) | MP4 H.264 (обязательно) + WebM VP9 или AV1 | ≤ 4 МБ |
| Мобильный (≤ 720 px по ширине) | MP4 H.264 + WebM | ≤ 1,5 МБ |
| Постер (первый кадр) | AVIF + WebP | ≤ 80 КБ |

Аудиодорожку удаляем.

#### Разметка и загрузка

- Атрибуты: `<video autoplay muted loop playsinline preload="metadata" poster="…">`. Без `muted` и `playsinline` видео не запустится в iOS и во встроенном браузере Telegram.
- Вариант видео (десктоп или мобильный) выбирается по `matchMedia` в острове `HeroVideo`. До гидрации показывается постер.
- Постер получает `fetchpriority="high"` и предзагружается. LCP-элементом должны быть постер или H1, а не само видео.

#### Поведение

| Условие | Что происходит |
|---|---|
| `prefers-reduced-motion: reduce` | Только постер, автозапуска нет |
| `navigator.connection.saveData` или медленное соединение (`effectiveType` 2g или slow-2g) | Только постер |
| Hero вне экрана или вкладка скрыта | Пауза (IntersectionObserver + `visibilitychange`) |
| Автозапуск заблокирован | Остаётся постер, ошибок в интерфейсе нет |

#### Доступность

- Видео декоративное: `aria-hidden="true"`, без нативных контролов.
- Видео играет дольше 5 секунд, поэтому по WCAG 2.2.2 нужна видимая кнопка «Пауза / Воспроизвести».
  - Кнопка доступна с клавиатуры и имеет локализованный `aria-label`.
  - Выбор пользователя сохраняется в `localStorage`.
- Текст поверх видео должен иметь контраст ≥ 4,5:1 на самых светлых кадрах. При необходимости оверлей усиливается относительно референса.

### 7.2 Marquee [новое]

- Бесконечная прокрутка на CSS-анимации.
- Второй экземпляр списка помечен `aria-hidden`.
- Анимация ставится на паузу при наведении и при фокусе внутри строки.
- При `prefers-reduced-motion` анимации нет: строка статичная, с переносом.

### 7.3 Мокапы телефона

**Экраны.** 8 экранов из `SS[lang]`:

| Ключ | Экран |
|---|---|
| `wallet` | Главный экран кошелька |
| `deposit` | Пополнение (с псевдо-QR) |
| `issue` | Выпуск новой карты |
| `setup` | Дизайн карты |
| `cards` | Мои карты |
| `freeze` | Заморозка карты |
| `wdUsdt` | Вывод USDT |
| `wdAlipay` | Вывод в Alipay |

**Реализация:**

- Экраны — серверные компоненты на HTML и CSS, не картинки.
- Внутренний дизайн экранов сохраняется. В стиле референса — только корпус и фрейм.
- Обёртка: `role="img"` и `aria-label` с названием экрана; всё внутри — `aria-hidden`.
- Масштаб задаётся CSS-переменной `--s`, без JS.
- Псевдо-QR переносится статичным SVG.
- Мокапы бывают перекрашиваемыми и фиксированными (тизер Projects, всегда в палитре ember).

### 7.4 Мокап админки (AdminShell)

- Тексты берутся из `ADM[lang]`, демо-строки — из прототипа.

### 7.5 BrandSwitcher

- Четыре кнопки с `aria-pressed`.
- Состояние хранится в атрибуте `data-brand` на `<html>` и в `localStorage` под ключом `fph-brand` (обращения в `try/catch`).
- Inline-скрипт в `<head>` применяет палитру до первой отрисовки.
- Палитра действует только внутри мокапов.
- При смене проигрывается анимация `swap`, кроме случаев с reduced motion.
- Событие: `brand_preview`.

### 7.6 LeadBlock (в стиле P8)

**Содержимое:**

- двухчастный заголовок `lead.h2` и подзаголовок;
- хэндл Telegram;
- чипы тем с `aria-pressed`;
- textarea с шаблоном `lead.tpl(topic)`, редактируемая.

**Кнопка «Copy message»:**

- копирует через Clipboard API;
- если копирование не удалось, выделяет текст в textarea и показывает `copyFail`;
- статус выводится в `aria-live="polite"`.

**Кнопка «Open Telegram»:** открывает чат, событие `submit_lead`.

Telegram не подставляет текст в чат с пользователем по ссылке, поэтому схема такая: сначала скопировать, потом открыть. Запасной сценарий обязан работать во встроенном браузере Telegram.

### 7.7 ShowcaseTabs (в стиле P4)

- Табы по паттерну WAI-ARIA Tabs: стрелки, Home и End, roving `tabindex`, `aria-controls`.
- Визуально — нумерованный список 01–04.
- Все четыре панели выводятся в HTML, неактивные скрыты через `hidden`.
- Событие: `tab_select`.

### 7.8 Header

## 12. Нефункциональные требования

### Производительность

- **JS:** не больше 150 КБ (gzip) на страницу. Запас увеличен под анимации.
- **Вес главной без видео:** ≤ 1 МБ.
- **Видео:** грузится после постера и не мешает LCP.
- **Сдвиги вёрстки:** мокапы и видео их не вызывают, CLS ≤ 0,05.

### Доступность (WCAG 2.1 AA)

- Skip link и видимый `:focus-visible`.
- Всё управляется с клавиатуры.
- Учитывается reduced motion: видео, бегущая строка и Reveal.
- Есть кнопка паузы видео.
- Контраст текста поверх видео и всех цветовых пар из токенов референса проверен.
- axe: 0 нарушений уровня critical и serious.

### Браузеры

- Последние две версии Chrome, Edge, Firefox и Safari.
- iOS Safari 16+.
- Android Chrome.
- Встроенный браузер Telegram на iOS и Android. Ручной прогон обязателен: навигация, автозапуск видео, копирование, переход в Telegram.

### Адаптивность

- Брейкпоинты берутся из референса.
- Минимальная ширина — 320 px.

### Безопасность (`_headers`)

- HSTS.
- `nosniff`.
- `Referrer-Policy: strict-origin-when-cross-origin`.
- `Permissions-Policy`.
- **CSP:**
  - `default-src 'self'`;
  - `media-src 'self'`;
  - `img-src 'self' data:`;
  - `connect-src` — только домен аналитики;
  - `frame-ancestors 'none'`;
  - в `script-src` в v1 допускается `'unsafe-inline'`, потому что Next.js в статическом экспорте добавляет inline-скрипты гидрации. Переход на хеши — задача в бэклоге.

### Ресурсы

Все ресурсы хостятся у нас. Сайт не делает ни одного запроса к домену референса или к его хранилищам.

## 13. CI/CD и качество

### Пайплайн

`install` → `typecheck` → `lint` → `check-headings` → `check-placeholders` (prod) → `build` → Playwright + axe → Lighthouse CI → деплой в Cloudflare Pages.

- Для каждого PR — превью-деплой.
- Продакшн деплоится из `main`.

### Сценарии Playwright (для обоих языков)

1. **Страницы.** Все страницы из раздела 5 отвечают 200, у каждой правильные `lang`, title, canonical и hreflang.
2. **Переключение языка.** Открывается та же страница; на главной сохраняется якорь.
3. **Корень.** `/` с `Accept-Language: ru` ведёт на `/ru/`, без заголовка — на `/en/`.
4. **Видео:**
   - запускается без звука;
   - кнопка паузы работает, выбор сохраняется;
   - при эмуляции reduced motion показывается только постер.
5. **Бегущая строка.** Останавливается при reduced motion.
6. **Табы Showcase.** Работают мышью и клавиатурой.
7. **BrandSwitcher.** Меняет мокапы и сохраняется между страницами; цвет не мигает при загрузке.
8. **LeadBlock.** Чипы, копирование (включая запасной сценарий), ссылка на Telegram.
9. **Мобильное меню.** Открывается и закрывается, Esc работает, фокус удерживается.
10. **404.** Неизвестный путь отдаёт 404-страницу с `noindex`.
11. **Внешние запросы.** Ни одного запроса к внешним доменам, кроме аналитики.
12. **Доступность.** axe на каждой странице.

### Визуальная сверка

- **Стиль.** Скриншоты на 1440, 768 и 390 px сравниваются с `docs/design-reference/screenshots/`. Сравнение по паттернам, а не попиксельное: контент у нас другой.
- **Контент.** Тексты сверяются с прототипом скриптом `check-headings` и ревью.
